# 00. 제품 원칙과 클린룸 규칙

## 1. 제품 원칙

1. **태어날 곳은 고를 수 없다.** 국가·성별·가정 형편은 실제 비율로 추첨한다. 돈을 내도 바뀌지 않는다.
2. **숫자는 엔진이, 이야기는 AI가.** 생사·소득·사건 발생 같은 결과는 통계 엔진이 결정한다. AI는 이미 정해진 결과를 서술할 뿐, 결과를 바꾸지 않는다. ("실제 통계 기반"이라는 신뢰가 제품의 핵심 자산)
3. **선택은 확률을 바꾸지만 운명을 정하지는 않는다.** 플레이어의 선택은 오즈(odds)를 움직이고, 결과는 여전히 확률로 정해진다.
4. **대부분의 삶은 평범하다.** 극적인 사건의 빈도는 실제 통계를 넘지 않는다. 드라마는 연출과 서사로 만든다.
5. **무거운 일은 그리지 않고 알린다.** 죽음·폭력·자살 등은 통계대로 일어나지만 장면을 묘사하지 않고, 도움받을 곳을 함께 안내한다. 15세 이상 대상.
6. **출처가 보이는 숫자.** 플레이어에게 보이는 통계 수치는 출처와 기준 연도를 확인할 수 있어야 한다.
7. **콘텐츠는 데이터다.** 이벤트·직업·갈림길은 코드가 아니라 DSL 데이터로 작성해, 기획자와 AI 파이프라인이 계속 늘릴 수 있게 한다.

## 2. 클린룸 규칙 (상용 출시 필수)

레퍼런스 서비스(1in8b.life)는 상용 서비스이므로 다음을 지킨다.

| 허용 | 금지 |
|---|---|
| 장르·컨셉·게임 메커니즘 참고 (아이디어는 저작권 대상 아님) | 레퍼런스의 JS 코드, CSS, 마크업 복사·변형 사용 |
| 공개 원천 통계(UN·세계은행 등)를 **직접** 수집·가공 | 레퍼런스가 가공한 데이터 테이블(국가표·보정계수 등) 사용 |
| 일반적인 UI 패턴(진행 바, 카드, 차트 등) | 레퍼런스 고유의 문구·카피·이벤트 텍스트·이름·로고·색 조합 |
| 화면 흐름의 일반 구조 참고 | 레퍼런스의 서비스명/유사 도메인 사용 |

- 레퍼런스 분석 사본은 프로젝트 저장소에 넣지 않는다.
- 모든 이벤트 텍스트와 코드는 새로 작성한다. AI로 생성한 콘텐츠도 레퍼런스 문장을 입력으로 주지 않는다.

## 3. 레퍼런스 대비 차별점

| 영역 | 레퍼런스 | Reborn |
|---|---|---|
| 서사 | 사전 작성된 템플릿 문장 | 엔진 결과 위에 AI가 그 사람만의 서사·편지·자서전을 생성 |
| 연출 | 텍스트·차트 중심, 단순 장면 | 장면 일러스트 레이어, 시간 흐름 연출, 지도 애니메이션, 사운드 |
| 콘텐츠 규모 | 단일 JS 파일 안에 하드코딩 | 이벤트 DSL + AI 보조 생성 파이프라인으로 직업·갈림길을 대량 확장 |
| 구조 | 3만 줄 단일 번들 | 엔진(순수 TS) / 콘텐츠(데이터) / UI 분리, 시드 기반 재현·테스트 |
| 저장 | 브라우저 로컬 + 이동 코드 | 로컬 우선 + 선택적 계정 동기화 |
