# 04. AI 서사 생성

## 1. 역할 분담

```
[엔진] 결과 결정 ──▶ [사실 요약 JSON] ──▶ [AI] 서술 생성 ──▶ [안전 필터] ──▶ 화면
                                         └ 실패/지연 시 ──▶ [템플릿 문장] ──▶ 화면
```

- AI는 **결과를 바꾸지 않는다.** 엔진이 정한 사실(누가, 언제, 무엇이 일어났는지)만 입력으로 받는다.
- AI 응답이 없어도 게임은 멈추지 않는다. 템플릿 문장이 먼저 보이고, AI 문장이 도착하면 부드럽게 교체한다.
- API 키는 서버에만 둔다. 클라이언트 → 우리 서버 라우트 → Claude API.

## 2. 생성 지점과 모델 계층

| 지점 | 빈도 | 분량 | 모델 계층 | 비고 |
|---|---|---|---|---|
| 연간 서사 한 줄 | 매년 (생애 60~80회) | 1~2문장 | 소형·저비용 (Haiku 계열) | 묶음 요청(3~5년치 사전 생성)으로 호출 수 절감 |
| 갈림길 상황 묘사 | 연 0~2회 | 2~4문장 | 소형 | 선택지 라벨은 템플릿 고정(게임 규칙과 일치 보장) |
| 이정표 장면·성찰 | 6~8회 | 짧은 문단 | 중형 (Sonnet 계열) | 플레이어가 남긴 한 줄을 다음 이정표에 반영 |
| 동반 출생자 근황 | 이정표마다 | 1문장 × 4 | 소형 | |
| 사망 기록 자서전 | 1회 | 400~800자 | 중형 | 무료 기본 |
| 장편 자서전·편지 (프리미엄) | 요청 시 | 수천 자 | 대형 (Opus 계열) | 기념품 패스 |

> 모델 ID·가격은 구현 시점에 최신 문서를 확인해 설정 파일(`ai.config.ts`)로 관리한다.

## 3. 입력 형식 (사실 요약)

```json
{
  "lang": "ko",
  "person": { "name": "…", "sex": "F", "age": 23, "country": "BGD", "urban": true, "household": 2 },
  "year": 2049,
  "facts": [
    { "type": "decision", "id": "edu.after_highschool", "chose": "work", "result": "success" },
    { "type": "job", "id": "garment_worker", "event": "start" },
    { "type": "stat", "happiness": -4 }
  ],
  "tags": ["new_start", "family_duty"],
  "recentNarrative": ["…지난 2년의 서사…"],
  "reflections": ["15세에 플레이어가 남긴 한 줄"],
  "tone": "neutral",
  "safety": { "softMode": false, "eduMode": false }
}
```

## 4. 프롬프트 원칙

- **2인칭 시점 고정**("당신은 …했습니다"), 담담하고 구체적인 문체.
- **사실 목록에 없는 사건을 만들어 내지 않는다.** (새 인물·사고·질병 창작 금지, 감정·풍경 묘사는 허용)
- 국가·문화 고정관념 금지, 실존 인물 언급 금지.
- `tone: heavy/sensitive` 사실은 결과만 짧게 서술, 방법·장면 묘사 금지.
- 출력은 JSON(`{"text": "…"}`)으로 받아 파싱 실패 시 템플릿으로 대체.

## 5. 안전 장치

| 단계 | 내용 |
|---|---|
| 입력 | 플레이어 자유 입력(한 줄 성찰, 마지막 한마디)은 위기 신호 감지 후 AI에 전달. 위기 신호 시 상담처 안내 우선 |
| 출력 | 금칙 패턴 검사(자해 방법, 혐오 표현 등), 길이·형식 검사, 사실 목록 외 고유명사 검출 |
| 모드 | 교육 모드·무서운 장면 빼기 모드에서는 heavy 사건 서술을 최소화 |
| 로그 | 문제 출력 신고 버튼 → 검수 큐 |

## 6. 비용·성능 관리

- 연간 서사는 미래를 미리 만들 수 없다(선택에 따라 달라짐). 한 해가 확정되는 즉시 템플릿 문장을 띄우고 AI 요청을 보내 도착하면 교체한다. 배속이 높을 때는 여러 해를 한 요청으로 묶는다.
- 프롬프트 캐싱으로 고정 시스템 프롬프트·국가 배경 설명 비용 절감.
- 사용자별 일일 한도, 비로그인 사용자는 저비용 계층만.
- 서버에서 동일 사실 요약 해시 → 결과 캐시.

## 7. 콘텐츠 생성 파이프라인 (오프라인)

"더 많은 직업·인생·갈림길"은 런타임 생성이 아니라 **오프라인 생성 + 검수**로 늘린다. (게임 규칙 일관성과 통계 정합성 유지)

```
[기획자 브리프] ─▶ [Claude: DSL YAML 초안 N개 생성] ─▶ [스키마·표현식·도달성 린트]
      ─▶ [시뮬레이션 1만 회 영향 리포트] ─▶ [사람 검수·수정] ─▶ [content/ 병합]
```

- 브리프 예: "남아시아 도시 저소득층 청년의 직업 10종과 각 직업 고유 사건 3개"
- 생성 시 통계 필드와 출처를 명시하게 하고, 근거 없는 확률은 린트에서 경고.
- 생성 프롬프트에 레퍼런스 서비스의 문장을 넣지 않는다 (클린룸).
